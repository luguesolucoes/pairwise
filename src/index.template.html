Activity

Everything this page does on the network is listed here.
    What this page sends over the network
    • The page makes no HTTP requests after it loads. Its Content Security Policy allows network connections only to the pairing brokers below, over WebSocket, so it cannot upload anything to a web server.
    • The connection offer travels inside the QR code. With automatic pairing on, the receiving device sends its connection reply back through public MQTT message brokers (__RELAYS__) over secure WebSockets. The reply is encrypted with a key derived from the QR code, so the brokers see only an opaque message of a few hundred bytes on a random-looking topic, plus both devices' IP addresses. With automatic pairing off, nothing goes to the brokers and the reply moves by a second QR code.
    • If STUN is on, each browser sends a small request to stun.l.google.com:19302 to learn its public IP address.
    • The text travels directly between the two browsers over a WebRTC data channel. WebRTC encrypts the channel with DTLS, and each 48 KiB chunk is additionally sealed with AES-256-GCM using a key that exists only in the QR code.
    • If you configure TURN, the encrypted stream may pass through that relay. It cannot read it.
    • Both devices' IP addresses are visible to each other, as with any direct connection.
